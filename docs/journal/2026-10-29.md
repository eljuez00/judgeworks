# 2026-10-29: Choosing a local LLM setup

## Goal

Install a local AI assistant on the MacBook Air that can write code, help build Python programs and use tools. It becomes the local development environment for the JudgeWorks harness. Document every step so others can repeat it.

## What we decided

See [decision 0001](../decisions/0001-local-llm-stack.md). In short: Ollama running Qwen 3.5 9B, with OpenCode as a terminal coding agent. The desktop PC becomes a bigger model server later, over a private Cloudflare tunnel.

## Things we learned

- **Ollama is not a Meta product.** Meta makes the *Llama* models; Ollama is an independent, MIT-licensed open-source project. The name is easy to confuse.
- **A model and a runner are different things.** Qwen is the model, a file of trained weights. Ollama is the program that loads it and answers requests.
- **Disk needed on the Mac is about 30 to 50 GB**, including a spare model and room to grow. An external SSD isn't needed for this. Models load faster from the internal drive, and stop working if an external drive is unplugged.
- **Ollama has no password.** It must never be exposed directly to the internet. Remote access goes through a private network.

## Update: 2026-10-31, tool connectors (MCP)

- We connected a third-party MCP tool server to OpenCode, and it showed as `Connected`.
- First request: OpenCode sent **14,477 prompt tokens** (agent instructions plus tool descriptions). The M5 read them at **about 600 tokens/s**, and the reply finished in 1 minute.
- Second request: **failed with HTTP 500 after 2.5 minutes.** The Ollama log showed:
  `qwen3.5 tool call parsing failed: XML syntax error ... element <function> closed by </parameter>`
  The 9B model wrote a malformed tool call, so Ollama couldn't parse it and OpenCode waited on a reply that never came.
- Memory peaked at 10.07 GiB with another heavy app open.

### Fix: OpenCode quietly fell back to a cloud model

- On one restart, OpenCode started on **"Flint 40B Free · OpenCode"**, one of its own free *cloud* models, instead of local Qwen. Anything typed there would have left the Mac.
- The fix was adding these to `opencode.json`:
  - `"disabled_providers": ["opencode"]`, which blocks OpenCode's built-in cloud models.
  - `"small_model": "ollama/qwen3.5:9b"`, so background tasks like naming sessions also stay local.
- We also used a dedicated agent with only the tools it needed and temperature 0.1.
- Check the config is valid after editing it: `python3 -m json.tool ~/.config/opencode/opencode.json`
- **Always check the bottom bar** reads `Qwen 3.5 9B (local) · Ollama (local)` before typing anything.
- Switch agents with **Shift+Tab**.

### Result

With those fixes, the tool session worked end to end. One thing to watch: the model correctly reported a value from a tool, then got its own arithmetic on that value wrong by a factor of two. Tool data is reliable; model arithmetic on top of it should be checked.

### Lessons

- Watch `~/.ollama/logs/server.log`. It shows prompt size, reading speed and tool-call errors that OpenCode doesn't show.
- Small models sometimes produce broken tool calls. A lower temperature, fewer tools and fresh sessions help.
- Long tool-heavy sessions are at the edge of what a 16 GB Mac can do. They belong on the desktop GPU.
